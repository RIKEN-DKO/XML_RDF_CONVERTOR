# XML-RDF Convertor 1.0

This tool converts metadata schemas defined as XML Schema (XSD) into OWL schemas.
The tool is developed in Python, and the executable file is `xml_rdf_convertor.py`.
Information required for the conversion is described in a rule file. This rule file can be generated by the program, and users can optimize the conversion by editing it.

## Requirements

- Python 3.10 or later is recommended
- Additional library:
  - `rdflib`

Example installation:

```powershell
pip install rdflib
```

## Functions

`xml_rdf_convertor.py` provides the following two functions.

- `schema`: XSD → OWL(Turtle)
- `instance`: XML (instance) → RDF(Turtle)

## Usage

### 1. XSD → OWL(Turtle)

```powershell
python xml_rdf_convertor.py schema your_schema.xsd --rules schema_rules.tsv -o schema.owl.ttl
```

If you want to create a new template rule file:

```powershell
python xml_rdf_convertor.py schema --init-rules schema_rules.tsv
```

### 2. XML (instance) → RDF(Turtle)

```powershell
python xml_rdf_convertor.py instance your_schema.xsd your_instance.xml --rules instance_rules.tsv -o instances.ttl
```

If you want to create a new template rule file:

```powershell
python xml_rdf_convertor.py instance --init-rules instance_rules.tsv
```

### 3. How to check the version of this program

```powershell
python xml_rdf_convertor.py --version
```

### OME Sample

OME (**Open Microscopy Environment**) is a project that develops open-source software and data format standards for storing and manipulating biological microscopy data.

- Official website: <https://www.openmicroscopy.org/>
- OME-XML documentation: <https://docs.openmicroscopy.org/ome-model/latest/ome-xml/>
- OME schema list: <https://www.openmicroscopy.org/Schemas/OME/>
- OME 2016-06 schema (`ome.xsd`): <http://www.openmicroscopy.org/Schemas/OME/2016-06/ome.xsd>

#### OME sample settings

- `examples/ome/ome_schema_rules.tsv`
  - Sample configuration for converting OME XSD → OWL
  - Verification (`verify`) is disabled for portability
- `examples/ome/ome_instance_rules.tsv`
  - Sample configuration for converting OME XML (instance) → RDF
- `examples/ome/ome_sample.xml`
  - Minimal sample for instance conversion

##### OME execution examples

```powershell
python xml_rdf_convertor.py schema ome.xsd --rules examples/ome/ome_schema_rules.tsv -o ome.owl.ttl
```

```powershell
python xml_rdf_convertor.py instance ome.xsd examples/ome/ome_sample.xml --rules examples/ome/ome_instance_rules.tsv -o ome_sample_instances.ttl
```

### SPASE Sample

SPASE (**Space Physics Archive Search and Extract**) is a metadata standard / data model for describing **heliophysics (Earth and space physics) resources** in a uniform way. According to the official website, it provides vocabularies and XML schemas for consistently describing resources such as Observatory, Instrument, Repository, and Numerical Data.

- Official website: <https://www.spase-group.org/>
- SPASE Base Model / human-readable model docs: <https://spase-group.org/data/model/index.html>
- SPASE XML Schema index: <https://spase-group.org/data/schema/index.html>
- SPASE 2.6.1 schema: <https://spase-group.org/data/schema/spase-2.6.1.xsd>

#### SPASE sample settings

- `examples/spase/spase_schema_rules.tsv`
  - Basic configuration for SPASE
  - `measurement.numeric_default=datatype`

##### SPASE execution examples

```powershell
python xml_rdf_convertor.py schema spase-2.6.1.xsd --rules examples/spase/spase_schema_rules.tsv -o spase.owl.ttl
```

```powershell
python xml_rdf_convertor.py schema spase-2.6.1.xsd --rules examples/spase/spase_schema_rules_measure_object.tsv -o spase_measure_object.owl.ttl
```

## About Rule Files

- Both JSON and TSV formats are supported.
- TSV uses the `key<TAB>value` format.
- Arrays are written as `key[]`.
- Dictionaries are written as `key[subkey]`.

Example:

```tsv
project.base_ns	http://example.org/ontology/
naming.lower_first_properties	true
measurement.unitless_literal_properties[]	sizeX
measurement.unitless_literal_properties[]	sizeY
```

## Notes on Editing Rule Files

- `project.base_ns` is effectively required. If it is not specified, the program issues a warning and continues with a temporary namespace (or stops in strict mode).
- When `measurement.numeric_default=object`, numeric items for which no unit pair (`*Unit`) can be found become warning targets.
- If necessary, you can set `validation.todo_patch_path` to output rule suggestions as TSV or JSON.
